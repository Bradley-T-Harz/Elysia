# Elysia 1.0.0 release notes

These notes describe the qualified stable Elysia v1.0.0 release. Public availability is established only by the canonical GitHub Release and Elysia Archive records, not by a mutable flag in this document.

Elysia 1.0.0 is the first whole-product stable release of the local-first governed Elysia platform. It combines the Desktop chamber and authenticated loopback Core with account-scoped Identity and Memory, conversations, projects, artifacts, requests and receipts, governed research, selected file/data/media stewardship, optional creator and scientific workers, lifecycle-managed profiles, Doctor, and the official bounded Codev extension.

The default Core is useful without a Website account, GPU, creator models, Codev, or cloud service. Optional Workstation/Research, Creator/Perception, Developer/Codev, Scientific/Engineering, Complete MEGA, and constrained Custom selections are resolved through the same authoritative component graph rather than source forks. Network access, large model acquisition, repository authority, update/repair mutation, and external export remain explicit governed operations.

Machine installation remains separate from personal autobiography. First run creates a real local account and encryption owner before voluntary onboarding may propose memories; the user can edit, select, reject, retain as draft, or later delete those account-scoped memories. Multiple local profiles remain isolated, and Local Admin governs installation-wide safety without universal access to private user content.

The release family includes reviewed source, Setup/bootstrap material, a one-file Core runtime, `.deb`, AppImage, the Codev VSIX and source, component/profile and model-acquisition manifests, notices/licenses, SBOMs, provenance, checksums, signatures, and verification material. Exact contents are authoritative only through the signed immutable release manifest.

Security boundaries include authenticated loopback Core, deterministic governance, Local-Admin-authorized installation-wide update/repair, fail-closed signed updater material, bounded rootless workers, no silent cloud fallback, no hidden shell or Git push in Codev, and sanitized receipts/diagnostics. The updater private key never ships; only its governed public trust root may appear in release artifacts.

Known carried obligations and externally scoped items are maintained in `KNOWN_ISSUES_v1.0.0.md`. The release bytes passed exact-candidate qualification; any replacement byte set requires a distinct identity, rebuild, rehash, resigning/reattestation, reinspection, and complete regression before publication.

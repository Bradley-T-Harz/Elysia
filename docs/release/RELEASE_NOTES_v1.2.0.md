# Elysia 1.2.0 candidate

This additive minor release carries the governed ScientificForge v0.2 typed
workflow substrate, scientific workspace/source authority, numerical verification,
scientific artifacts and request/node provenance. Existing v0.1 scientific
operations, legacy math and public/private research partitioning remain available.

Model fallback now obtains a fresh compute admission. A Reflex miss receives a
model budget before invocation. Exact model/hardware profiles can use isolated,
request-owned Ollama providers with wall deadlines, thermal supervision and
verified process-group termination. Model selection remains role/policy driven.
Mistral remains available; a measured hybrid profile is slow and may be thermally
limited. Granite and StarCoder have separate bounded normal-runtime proofs.
Those source proofs do not alone establish installed qualification.

The release follows the existing major.minor.patch product identity and the
previous additive 1.0-to-1.1 release precedent. Elysia advances to 1.2.0; unchanged
Codev Core/adapter product contracts remain 1.1.0, the shared native runtime
compatibility identity remains 1.1.0, and API protocol remains 1.0.0. Product,
component and protocol versions are deliberately separate. Historical artifacts,
tags and release notes remain intact.

The Core package includes NumPy, SymPy and Pint adapters. SciPy and HiGHS adapters
are source-supported optional capabilities and are unavailable when those
backends are absent from the executing runtime. Development-environment installs
are not package dependencies. LP/MILP use isolated HiGHS workers with independently
checked feasibility and bounded work; they are not arbitrary code execution.
The six proposed scientific Add-ons are not claimed as completed or installed.
Geospatial/environmental and full Watershed readiness remain partial; the final
challenge has not been run.

Publication is conditional on the exact candidate's backend, frontend, package,
installed-runtime, privacy and signing gates. Only publisher-signed manifests and
canonical release assets establish a qualified stable download. This document
is not a claim that publication or qualification has already occurred.

# Publication-bound history and private continuity contract

## Repository roles

Elysia and individually approved Add-ons are publication-bound repositories.
They must contain portable public source, reviewed doctrine, synthetic fixtures,
and privacy-safe Git history before any first public push.

Website, Artisan, and company repositories remain private under current release
law. Their histories, production account state, roles, badges, records, and
private operational evidence are not inputs to a public Elysia/Codev rewrite.
They must not be rewritten or centralized merely to prepare public Core source.

## Private continuity

Operator profile facts, personalized prompts, machine facts, identity media,
runtime databases, journals, logs, credentials, and pre-sanitization histories
belong only behind the approved private/local boundaries. Credentials are never
profile material. A private profile seed is an inert recovery aid and is not
authorized for automatic import.

## Public history gate

The reviewed public-source artifact is the exact file set selected by
`packaging/public_manifest.yaml`. Historical/internal evidence under
`docs/reports/`, architecture snapshots, and benchmark notebooks remain
preserved in the local development repository but are not members of that
artifact. The `--scope public` verifier must pass before the artifact can enter
Pass 10D qualification. The strict `--scope tree` verifier remains available
and must continue to report excluded internal material rather than silently
pretending the whole development worktree is public-safe.

If Git refs themselves are proposed for publication, every reachable branch,
tag, stash, internal ref, commit message, author/committer email, historical
path, and blob must separately pass the strict publication-history verifier.
The current local development refs are not authorized publication artifacts;
Pass 10D may not push them merely because the reviewed source archive passes.
The operator may supply extra exact private markers through an untracked file.
Findings report categories, hashes, and relative paths only—never matched
content.

History rewriting requires verified private bundles and restore instructions,
an exact rewrite plan, a disposable dry run, complete history scans, ref checks,
source tests, and package tests. The canonical rewrite must be identical to the
proved dry run. Unreachable private objects may be pruned only after those gates
pass. The private bundles are never publication artifacts.

## Product preservation law

Privacy sanitation must preserve Elysia's philosophy, personality, ecological
identity, moral doctrine, governance law, and product behavior. It must never
be used to justify removing an established product surface. An incomplete or
broken established capability is a requirement to repair, harden, and test it,
not permission to hide, redirect, disable, or delete it. Named removal requires
the release owner's explicit approval.

## Publication state

This contract authorizes no push, release, package upload, Marketplace listing,
or public remote. Final publication remains a separate Pass 10D decision.
